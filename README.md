# 智能文档填充系统（AI Autofill Web）

上传 Word / Excel 模板 → 自动识别需要填写的位置 → 优先从知识库匹配内容 → 逐项确认 → 下载填好的文件。

面向两类重复劳动场景：

- **项目申报**：不同项目的申报表格式各异，但公司信息、项目信息基本重复
- **求职应聘**：不同公司的应聘表格式不同，但个人信息完全一致

系统会记住你上传过的已填写文件，把它们变成知识库，下次填新模板时自动套用。

---

## 快速开始

```bash
npm install
npm start
```

浏览器打开 <http://localhost:3000>

> 部署到云服务器（Ubuntu）：见 **[DEPLOY.md](DEPLOY.md)**，含 systemd、Nginx、HTTPS、Docker 方案。

### 想立刻看到效果

```bash
npm run samples   # 生成 5 个示例模板/已填文件到 samples/
npm run demo      # 创建两个示例档案并导入示例知识（需先 npm start）
```

然后用 `samples/项目申报表模板.xlsx` 试填即可。

## 使用流程

### 一、先让系统"学会"你的资料（只需做一次）

> 🔒 知识库内容仅保存在本地，杜绝信息泄露——数据存在你自己的浏览器里，不会上传到服务器。

1. 打开 **知识库** 页 → **＋ 新建档案**
   - 建议按场景分档：`个人求职资料`、`公司项目申报资料`
   - 系统自带一个 `默认知识库（示例）`，含 10 条示例数据，工作台默认选中它
2. 选好档案 → **📥 上传已填写文件学习**
3. 系统识别字段 → 弹窗里核对（可取消勾选不想存的内容，如身份证号）→ **保存到知识库**
   - **配置了 AI**：由模型理解表格布局后抽取，能正确处理「标签 | 值 | 标签 | 值」连续排列的表格；返回的每个值都会校验是否**逐字出现在原文**中，找不到的直接丢弃，不会编造
   - **未配置 AI**：退回规则抽取（冒号对、相邻单元格），对复杂表格准确率有限
4. 重复上传你手头的历史已填文件，知识库会越来越全
5. 也可以 **＋ 手动添加** 单个字段

### 二、填新模板

1. **填充工作台** → 选择对应档案 → 上传 `.docx` / `.xlsx` 模板
2. 系统解析文档结构 → 规则识别填充位 →（配置 AI 后）AI 精判并规范字段名
3. 确认页逐项检查：每行显示 **建议值 / 来源 / 把握**
   - 来源标记：`知识库·精确` `知识库·同义` `知识库·匹配` `知识库·模糊` `AI 填充` `自动·日期`
   - 值可以直接改成任何内容，不勾选则不填
4. **确认并生成文件** → **下载填充后的文件**

原模板的字体、表格、合并单元格、复选框都会保留，只往空位里写值。

## AI 配置（可选，但推荐）

打开 **设置** 页，选择服务商后填写 Key（默认 DeepSeek）：

| 服务商 | API 地址 | 模型 | Key 获取 |
| --- | --- | --- | --- |
| **DeepSeek（默认）** | `https://api.deepseek.com` | `deepseek-chat`（推荐）<br>`deepseek-reasoner`（推理增强） | <https://platform.deepseek.com/api_keys> |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` / `glm-4-plus` | <https://open.bigmodel.cn> |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` / `gpt-4o` | <https://platform.openai.com/api-keys> |
| 自定义 | 任意 OpenAI 兼容地址 | 该服务的模型名 | — |

点 **测试连接** 验证，成功后点 **保存配置**。

**AI 负责什么：**

- **从已填文件中抽取信息**（知识库学习）：理解表格布局，判断「标签 / 值」配对；返回值需逐字出现在原文中，防止编造
- 判断哪些位置确实需要填（排除标题、说明文字）
- 把「申请人 / 姓名 / 填报人」这类同义叫法归一为同一字段
- 自动分类（个人信息 / 联系方式 / 教育背景 / 工作经历 / 公司信息 / 项目信息）

**不配 AI 也能用**：规则引擎负责识别填充位置，知识库的精确 / 同义词 / 包含 / 模糊四级匹配负责找值，日期类字段自动填当天。但**复杂表格的信息抽取准确率会明显下降**，建议配置 AI。

## 识别能力说明

| 模板样式 | 示例 | 支持 |
| --- | --- | --- |
| 下划线占位 | `项目名称：____________` | ✅ 替换整段下划线 |
| 空括号占位 | `申请人：（      ）` | ✅ 替换整个空括号 |
| 冒号后留白 | `联系电话：` | ✅ 冒号后追加 |
| 表格标签格 + 值格 | `[申请人：][    ]` | ✅ 写入右侧值格（含合并单元格） |
| 表格表头 + 数据行 | 表头`姓名/单位`，下一行留空 | ✅ 写入表头下方空格 |
| 竖排表单 | 标签在上、值在下 | ✅ 写入下方值格 |
| **子明细表** | 学习经历 / 工作经历 / 家庭成员等 | ✅ **按列名匹配整表填入**（多行多列） |
| 复选框 | `□男 □女` | ✅ 跳过，不会破坏 |
| 合并单元格 | `B2:D2` | ✅ 写入主格 |
| 字体样式 | 宋体/仿宋、字号、加粗 | ✅ 填入的内容继承模板原有字体 |
| 旧格式 | `.doc` / `.xls` | ❌ 请先另存为 `.docx` / `.xlsx` |

### 子明细表是怎么处理的

识别时会把这些表单独抽出来，按「表名 + 列名 + 每行数据」整表存进知识库（值直接取自单元格，不经过模型，不会有幻觉）：

```
学习经历       起止年月 | 毕业院校及专业 | 学历 | 学位 | 学习方式
               2012.09-2016.06 | 成都东软学院软件工程专业 | 本科 | 学士 | 全日制
```

支持三种常见版式：

| 版式 | 样子 |
| --- | --- |
| A. 段名在列头行首格 | `[学习经历] 起止年月 | 毕业院校及专业 | 学历` |
| B. 段名单独一行（表格内） | `家庭成员情况` / 下一行 `关系 | 姓名 | 政治面貌` |
| C. 段名是表格上方段落 | 段落 `家庭成员情况` + 表格 `关系 | 姓名 | 政治面貌` |

填写时按**列名**匹配（不是按行号位置）：

- 列名容错：`起止时间`↔`起止年月`、`工作单位及职务`↔`工作单位及岗位`、`出生年月`↔`出生日期`、`证明人`↔`联系人`
- 只填空白行，已有内容的行不覆盖
- 知识库里的「无」不写入，且该格不会再被通用字段填充（避免把手机号填进"证明人电话"）

## 项目结构

```
autofill-web/
├─ server/
│  ├─ index.js              Express 入口（默认仅监听 127.0.0.1）
│  ├─ routes/
│  │  ├─ fill.js            上传模板 / 任务轮询 / 写回 / 下载
│  │  ├─ kb.js              档案与条目 CRUD / 学习上传
│  │  └─ settings.js        AI 配置读写与连接测试
│  └─ services/
│     ├─ ai.js              智谱 / OpenAI 兼容客户端（无 Key 自动降级）
│     ├─ parseDocx.js       docx 解析与写回（改 XML，保留格式）
│     ├─ parseXlsx.js       xlsx 解析与写回（exceljs，保留样式）
│     ├─ detector.js        规则识别填充位（含表格结构感知）
│     ├─ learn.js           从已填文件抽取字段值对 + 规则分类
│     ├─ knowledge.js       档案存储 + 四级匹配（精确/同义/包含/模糊）
│     ├─ fill.js            分析流水线与写回编排
│     └─ storage.js         JSON 持久化
├─ public/                  三个页面（原生 HTML/CSS/JS，无构建步骤）
├─ samples/                 示例模板（npm run samples 生成）
├─ scripts/                 样例生成 / 演示数据 / 端到端测试
└─ server/storage/          运行时数据（上传件、结果、知识库）
```

## 设置页与监控台的访问权限

| 场景 | 访问方式 |
| --- | --- |
| 本机（开发或服务器上） | `localhost` / `127.0.0.1` 直接打开，免登录 |
| 远程（部署后） | 需要设置 `ADMIN_PASSWORD`，打开 `/admin-login.html` 登录；7 天内免登录 |

开启远程管理（服务器上）：

```bash
sudo bash -c 'cat > /etc/autofill.env' <<'EOF'
ADMIN_PASSWORD=你的强密码
EOF
sudo chmod 600 /etc/autofill.env
sudo systemctl restart autofill
```

- 密码只存在环境变量里，不进代码、不进数据库
- 会话为 HMAC 签名 Cookie（HttpOnly + SameSite=Lax，HTTPS 下加 Secure），改密码后旧会话全部失效
- 同 IP 连续 5 次密码错误锁定 10 分钟
- 未设 `ADMIN_PASSWORD` 时保持"仅本机可访问"，远程返回 403

> **必须先启用 HTTPS 再开远程管理**，否则密码是明文传输。

## 监控台（访问统计）

通过 `localhost` / `127.0.0.1` 访问 `/admin.html`，或在导航栏点「监控台」。**仅本机可访问**（远程访问返回 403，导航里也不显示入口）。

统计内容：

| 指标 | 说明 |
| --- | --- |
| 总访问量 | 页面浏览次数（三个页面合计），按天分列 |
| 独立访客 | 按浏览器匿名 ID 去重 |
| 完成自动填充文件 | 每次「确认并生成文件」成功计 1 |
| 文件下载次数 | 每次下载成功计 1 |

访客信息记录：匿名访客 ID、**地区（省/市）**、设备/浏览器/操作系统、语言、时区、屏幕尺寸、来源页面、首次与最近访问时间、**脱敏 IP**（如 `192.168.*.*`）。

关于地区：

- 通过第三方免费接口 `ip-api.com` 根据 IP 推算，精确到省/市，带运营商信息
- 查询结果按**网段哈希**缓存 30 天（IPv4 取前三段、IPv6 取前四组），缓存里不存原始 IP
- 内网/本机地址直接标记为"本机/内网"，不外发
- 如需完全关闭该功能（不外发任何 IP）：启动时设置 `GEOIP=off`

隐私约束（重要）：

- **不保存原始 IP**，只存脱敏值
- **不记录文件名、不记录知识库内容**
- 访客表最多 2000 条、事件明细最多 200 条、按天统计保留 90 天
- 统计文件在 `server/storage/data/metrics.json`（可用 `STORAGE_DIR` 改位置）

> 注意：地区查询需要把访客 IP 发送给 ip-api.com。如果你的合规要求不允许外发 IP，请设 `GEOIP=off`，此时地区列显示为空。

远程服务器上查看监控台：

```bash
# 方式 1（推荐）：设置 ADMIN_PASSWORD 后直接登录
#   https://你的域名/admin.html  → 跳转登录页 → 输入密码

# 方式 2：SSH 隧道（不设置密码时）
ssh -N -L 127.0.0.1:3001:127.0.0.1:3000 root@服务器IP
# 本地浏览器打开 http://127.0.0.1:3001/admin.html
```

## 数据存储

### 知识库：只存在访问者的浏览器里

- 知识库内容保存在浏览器 **localStorage**（键名 `autofill.kb.v2`），**不会上传到服务器**
- 部署到服务器后，每个访问者的资料互相隔离、互不可见
- 换电脑 / 换浏览器 / 清缓存会丢失，请用知识库页面的 **「导出备份」** 迁移，新设备 **「导入备份」** 还原
- 内置一个 **默认知识库（示例）**，含 10 条示例数据，工作台默认选中它；可随意修改或删除

### 服务器上保留什么

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| AI 配置（API Key、模型） | `server/storage/data/settings.json` | 部署时由管理员配置一次 |
| 上传的文档 | `server/storage/uploads/` | **写回后立即删除**；残留超过 2 小时自动清理 |
| 生成的文档 | `server/storage/outputs/` | **下载后 10 分钟删除**；残留超过 2 小时自动清理 |
| 旧版知识库（历史遗留） | `server/storage/data/kb-*.json` | 已停用，仅用于一次性迁移到浏览器 |

服务默认只监听 `127.0.0.1`；如需局域网/公网访问：`HOST=0.0.0.0 npm start`（请自行加反向代理与访问控制）。

### 设置页仅本机可访问

设置页含服务器上的 AI 密钥配置，因此：

- 通过 `localhost` / `127.0.0.1` / `[::1]` 访问：显示「设置」入口，可正常配置
- 通过 **IP 或域名**访问：导航栏自动隐藏「设置」，直接访问 `/settings.html` 返回 403 提示页，`/api/settings*` 接口同样拒绝

判定依据是请求的 Host 头（不是来源 IP），所以反向代理要**透传 Host**（Nginx 默认 `proxy_set_header Host $host` 即可）。若代理把 Host 改写成 localhost，远程访问会被误判为本机，务必保持透传。

需要远程改配置时，用 SSH 隧道之类的方式把服务映射到本机后再用 localhost 访问。

### 旧版本数据迁移

如果之前用旧版本存过服务端知识库，首次打开新版页面会自动把它们搬到当前浏览器（一次性），之后服务端不再保存。写入接口已返回 `410 Gone`。

## 说明与限制

- 一份模板的识别上限为 150 个候选位置、扫描前 300 行 × 60 列
- 扫描件 / 图片型表格（非真实文本）无法识别，需要 OCR
- AI 只会"照抄"知识库里的值；知识库没有的内容留空由你填写，避免编造信息

### 安装失败（Windows）

若 `npm install` 报权限错误（如 `EACCES ... node_cache`），说明 npm 全局缓存目录不可写，改用用户目录缓存：

```bash
npm install --cache "%USERPROFILE%\.npm-cache"
```
